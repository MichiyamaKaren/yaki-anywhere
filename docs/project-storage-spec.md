# 项目与私有存储 spec

确认日期：2026-10-16。当前实现范围为 Web 和 Capacitor Android。

## 项目管理

- 每个项目包含一份 ASS 私有副本、校对状态、项目名称和视频关联。
- 导入 ASS 总是创建新项目，允许同名文件；保留已有项目，不原地修改导入文件。
- 侧边栏仅保留“项目管理”导航入口，项目列表在独立的 `#/projects` 页面以卡片展示；手机顶部“项目”按钮进入同一页面。支持前进、后退和刷新，返回工作台时保留内存编辑内容与滚动位置；进入项目管理暂停视频。
- 支持打开、重命名、关闭、删除、关联或更换视频。删除需在界面确认，仅删除私有数据，不修改原文件。
- 打开工程（包括启动时恢复上次工程、切换工程和点击当前工程卡片）时，按 ASS 条目顺序选中第一条未校对字幕，并将视频定位到其开始时间，保持暂停；全部已校对时定位到第 1 条，空工程保持 0 秒。视频稍后加载或重新授权后仍保留该定位。
- 切换或关闭项目时有未保存修改，必须选择保存、放弃或取消；保存失败留在当前项目。

## 保存规则

- 加载项目时解析 ASS 到内存，文本与时间修改仅更新内存，不保存逐条变更日志或逐条修改时间。
- 普通编辑和手动确认校对只标记未保存；“保存”按钮 / Ctrl 或 ⌘ S 更新私有项目。
- 自动批准开启且存在未保存修改时自动保存；关闭后不再触发普通编辑的自动保存。
- 切后台时有修改就保存，无修改不写入。后台事件包括网页隐藏 / pagehide 和 Android pause；异常终止不能保证尚未完成的异步写入。
- 不使用停顿 1 秒、最长 10 秒或其他周期保存规则。时间轴拖动不在中途触发普通自动保存，提交后再保存；后台保存可以保存当前内存状态。
- 显式导入 ASS、关联视频、删除项目会持久化该操作；关联视频不会顺带保存普通模式下尚未保存的字幕修改。
- 自动批准产生的状态、手动保存、后台保存共用同一串行保存入口。保存中出现的新修改仍标为未保存。
- 导出与保存独立：导出外部 ASS 不包含校对 bitmap，也不把当前项目标记为已保存。

## 数据格式与一致性

- 私有 ASS 采用 UTF-8 BOM，保留样式、标签、Comment 和非编辑事件；不保证原编码或逐字节一致。
- 校对状态按可编辑 Dialogue 顺序打包为 bitmap，0 为未校对、1 为已校对。JSON 边界使用 Base64 编码，仍是一位一条。
- 项目元数据包含 `schemaVersion`、`id`、`name`、`assName`、`revision`、`assHash`、`entryCount`、`reviewedCount`、`reviewedBits`、私有 ASS 引用和 `video`。
- 修改文字或时间清除对应校对位。导入新项目全部未校对；迁移时保留旧状态。
- SHA-256 针对 ASS 内容计算，忽略可被文件读取器消费的开头 BOM。加载时校验哈希、Dialogue 数量、bitmap 长度和多余位。
- 状态不匹配时仍允许读取 ASS，全部按未校对打开并明确提示；用户可保存修复后的状态。
- 先完成新的 ASS 写入，再原子提交指向该文件的元数据和状态；提交失败保留上一份完整版本。ASS 未变化时复用原私有文件。
- 使用 `revision` 检查旧窗口的保存和删除操作，冲突时拒绝静默覆盖，允许导出当前内容后重新打开。
- 不保留历史版本列表；保存接口和项目级版本字段可供以后扩展快照。

## 平台存储

### 网页

- ASS 优先存 OPFS 的 `yaki-projects` 目录，不支持时使用 IndexedDB Blob。
- IndexedDB `yaki-projects` 数据库的 `projects` 表存元数据、bitmap 和视频句柄，`settings` 表保存上次打开的项目。
- 视频通过用户选择获得只读 `FileSystemFileHandle`，不保存视频副本。再次打开检查授权，重新取得 File 并生成临时播放地址。
- 不支持句柄的浏览器只保存文件名、大小、最后修改时间，提示下次重新关联；不把 File / Blob 或临时播放地址持久化。
- 权限失效时可点击“允许访问视频”；原文件不可用时重新关联；大小或修改时间变化时提示原文件已变化。
- 需要安全上下文（HTTPS 或 localhost）。存储按站点来源隔离，切换端口、浏览器资料或设备不会共享项目。
- 站点私有存储不提供对有权限访问浏览器资料的本机进程的强隔离。

### Android App

- ASS、视频和 SQLite 位于内部 `getNoBackupFilesDir()/yaki-projects/`，关闭系统备份，不使用共享存储。
- 仅通过系统选择器读取原视频，以固定大小缓冲区流式复制；已知大小时检查剩余空间，复制时发送进度。
- 保留可识别的视频扩展名，以便 WebView 正确处理媒体类型；不通过 Base64 或整个 Blob 将大视频传过 JS 桥。
- 完成复制后才提交新视频关联，再清理旧视频；失败或取消保留旧关联。启动时清理复制或保存中断留下的未引用私有文件。
- 播放器及频谱读取同一私有视频；频谱通过分段 URL 读取，继续保留有限缓存。
- 对外只有用户主动导出的 ASS；不向其他 App 授予项目私有文件读取权限。

## 迁移和验证

- 从 `localStorage` 的 `yaki-project-v1` 迁移为固定迁移标识项目，保存并重新读取校验成功后才移除旧草稿。
- 迁移重试不重复创建项目；失败不删除旧数据。
- 测试覆盖 bitmap、BOM 哈希、IndexedDB / OPFS 路径、失败恢复、版本冲突、视频引用、迁移中断与保存规则。
- 网页预览确认后再生成 APK；Android 编译检查不等于设备兼容性验证。
